围绕人机协作场景中共情感知量表的自动化构建，本阶段已完成 EmpathyScale 多智能体生成流程的设计、实现与场景验证。系统以 Boateng 等人提出的九步量表开发规范为理论框架，并参照 Schmidmaier 等人（2024）PETS 感知共情量表的开发思路，将“领域识别—题项生成—内容效度—模拟施测—统计精简—结构验证”等环节组织为可复现的流水线。在肌肉骨骼机器人并肩装配、共享工具架等典型场景中，系统可输出经模拟评估与 EFA/CFA 筛选后的场景专用量表（如 10 条最终题项），并支持与 PETS 通用量表、单提示直出等基线进行定性对照，形成完整证据链。

## 1. 背景

在人机协作（Human-Robot Collaboration, HRC）评价研究中，感知共情（perceived empathy）是衡量协作体验与信任的重要构念。然而，共情并非脱离情境的抽象特质：协作方式（并肩/面对面/远程）、资源关系（共享工位、工具架、角色分工）、沟通渠道（口语、动作观察、视觉提示、接触反馈）以及机器人形态（肌肉骨骼、协作臂、移动平台等），都会改变“何谓共情表现”的可观察内涵。

以 Schmidmaier 等人提出的 PETS 量表为例，其条目多指向“系统是否理解我”“是否有情商”等跨情境抽象判断，在跨场景可比性上具有优势，但在具体工位协作中，往往难以区分以下机制差异：

- 共享工位上同时伸手取件时的口头让行（如“你先拿”）；
- 通过手臂轨迹预判对方意图；
- 几乎碰撞或轻微接触后的沟通修复与安全顾虑。

若仅依赖通用量表或单次 LLM 提示直接生成条目，容易出现三类问题：**构念漂移**（条目偏离场景失败模式）、**可核验性不足**（难以对应具体可观察行为）、**结构不稳定**（多次生成维度与条目数波动大）。

为此，本仓库采用 **场景驱动的共情量表生成方法 EmpathyScale**：以结构化访谈锁定评价边界，以文献检索抽取可测量机制，经多智能体协同生成题项池，再通过 empathic / non-empathic 双组 Persona 模拟施测与 EFA/CFA 统计精简，最终输出可追溯、可解释、可复现的场景专用量表。该方法在理论上对齐 Boateng 九步规范与 PETS 六段流程，在工程上以 Python 多智能体流水线实现，每个 run 在 `data/runs/{run_id}/` 下保存完整中间产物。

## 2. 共情量表生成方法 EmpathyScale

### 2.1 总体架构

EmpathyScale 将量表开发过程分解为职责明确的智能体组，按固定顺序串联执行。整体数据流为：

**用户/场景输入 → 访谈智能体组 → 文献检索智能体组 → 量表生成智能体组 → 评估智能体组（Phase 1）→ 统计选题 → 评估智能体组（Phase 2）→ 定稿量表**

各阶段输出写入统一 run 目录，形成从场景描述到终版条目的完整证据链。与 PETS 原文 Figure 1 六段流程的对应关系如下：访谈 + 文献检索对应 **Domain Identification**；多生成器题项生成对应 **Item Generation**；内容评估与语义去重对应 **Item Validation**；Phase 1 双组 Persona 施测对应 **Item Testing**；EFA 链对应 **Item Reduction**；CFA + Phase 2 验证对应 **Scale Evaluation**。

### 2.2 场景结构化输入：访谈智能体与场景因子

#### 2.2.1 访谈智能体组

**访谈智能体组（Interview Agent Group）** 面向目标协作场景开展结构化信息收集。系统支持两种入口：交互式 `main.py` 对话采集，或预定义场景脚本 `run_predefined_scenarios.py` 直接注入场景文本。

访谈输出统一写入 `interview_agent_group/summary.json`，核心字段包括：

| 字段 | 含义 | 对题项生成的作用 |
|------|------|------------------|
| `assessment_context` | 评价情境总述 | 量表 Purpose 段落的场景锚点 |
| `robot_platform` | 机器人平台类型 | 约束条目中的主体与能力描述 |
| `interaction_modalities` | 交互方式（口语/视觉/接触等） | **关键字段**：决定条目可观察渠道 |
| `collaboration_pattern` | 协作分工模式 | 区分“谁拿哪类零件”等行为语境 |
| `environmental_setting` | 环境设定 | 工位、工具架等空间要素 |
| `expected_empathy_forms` | 期待的共情表现 | 正向行为清单 |
| `failure_modes` | 典型失败模式 | **关键字段**：决定条目应覆盖的协调风险 |

其中 **交互方式** 与 **失败模式** 被视为最关键输入：前者防止条目脱离可观察渠道（如场景仅有短句口语 + 手臂动作，却生成“系统理解我内心”类抽象条目）；后者确保量表覆盖同时伸手、挡路、接触无解释等真实协调失败类型。

访谈组内由四个子智能体分工：TaskCollector（任务与活动）、EnvironmentAnalyzer（环境与工位）、PlatformSpecialist（平台能力）、CollaborationExpert（协作模式与交互方式），最终汇总为结构化摘要。

#### 2.2.2 场景因子抽取

在访谈摘要基础上，**场景因子模块（`utils/scenario_factors.py`）** 从文本中抽取通用协作机制标签，用于驱动文献检索 query 与题项约束。因子分组包括：

- **interaction_modes**：side-by-side、face-to-face、remote、turn-taking 等；
- **resource_relations**：shared workspace、tool rack、contention、role-constrained division 等；
- **communication_modes**：language、action observation、visual cues、haptic/contact 等；
- **robot_type**：musculoskeletal、humanoid、collaborative arm 等；
- **risk_factors**：physical contact/collision、shared-space interference、safety concern 等；
- **embodied_cues**：embodied motion、visible bodily limitation 等。

以肌肉骨骼并肩装配场景为例，访谈摘要可概括为：人与肌肉骨骼机器人并肩坐在装配工位，共享工具架；人负责需判断的精细操作，机器人负责较重或靠其一侧的零件；协调失误可导致同时伸手、挡路及轻微接触。期待的共情形式包括及时表明意图、主动让行、为人在工具架处留空间、考虑人体舒适距离等；失败模式包括双方同时取件、假设对方已看到自己的伸手、挡路或擦碰、接触后无暂停/避让/解释。

### 2.3 文献驱动的机制卡片

#### 2.3.1 文献检索与筛选

**文献检索智能体组（Literature Search Agent Group）** 在访谈摘要基础上自动生成 5～6 组检索 query，面向 arXiv、Semantic Scholar 等来源检索 HRI、心理测量与协作行为相关文献。检索策略采用 **双优先级**：其一，机器人共情量表构建方法；其二，协作情境中机器人共情的理解方式。每个 query 每源目标检索约 20 篇，经 LLM 相关性打分（1～5 分）后保留 ≥3 分的文献，最多筛选 80 篇；从中抽取 definitions、behaviors、measurement 等类别发现，并下载 PDF 归档至 `pdfs/{category}/` 目录（目标最多 50 篇）。

query 生成并非泛化检索，而是由场景因子驱动：例如共享工位协调、碰撞后适应、显式沟通修复、动作观察隐性协调等意图，会映射为不同的检索式，使后续证据与场景失败模式对齐。

#### 2.3.2 机制卡片聚合

文献抽取结果进一步经 **机制卡片构建（`utils/mechanism_card_builder.py`）** 聚合为 scenario-linked mechanism cards。每张卡片记录：

- **mechanism_type**：如 shared_workspace、collision_contact、communication_repair 等；
- **supported_by**：支撑文献标题列表；
- **scenario_link**：场景迁移说明；
- **measurement_implications**：测量启示（条目应观察什么）；
- **related_factors**：与已知场景因子的关联。

该步骤将 Boateng 框架中的“领域识别 + 理论依据”计算化：题项生成不仅依赖场景描述，还受文献机制约束，使条目具备可追溯证据来源。以一次实际 run 为例，初始量表草稿 `scale_draft.md` 在 Evidence Base 中列出高相关文献（如 human-robot proxemics、contact-based PHRI 等），并标注各维度证据覆盖情况。

### 2.4 题项生成与内容筛选

#### 2.4.1 构念界定与多生成器并行

**量表生成智能体组（Empathy Scale Generation Agent Group）** 接收访谈摘要、文献摘要、专家 PDF 与机制卡片，分阶段完成题项池构建。

**第一步：构念/维度界定（Construct Definition）**  
结合场景与文献，由 LLM 输出维度框架。以上述肌肉骨骼场景为例，初始草稿划分三个维度：**Spatial Coordination Understanding**（空间协调理解）、**Collision-Responsive Adaptation**（碰撞响应适应）、**Explicit Communication Repair**（显式沟通修复），并规定 5 点李克特计分。

**第二步：多生成器并行题项生成（Multi-generator Item Generation）**  
默认启用 **3 个并行生成器**（`num_item_generators=3`），在不同 prompt 约束下产出候选条目，再合并为题项池。条目写作规范强调：

- 第一人称、过去时或一般体验陈述（“The robot said ‘你先拿’ when we both reached…”）；
- 锚定可观察行为（口头短语、手臂暂停、轨迹变化），避免“robot has emotional intelligence”类抽象判断；
- 覆盖 `failure_modes` 中的协调风险点。

一次典型 run 由 3 个维度共生成 **36 条** 候选题项（每维 12 条），写入 `scale_draft.md`。

#### 2.4.2 内容评估与语义去重

生成后进入内容筛选链：

1. **内容评估（Content Assessment，默认开启）**：LLM 对条目清晰度、场景贴合度、可观察性打分，剔除或改写低质量条目；
2. **语义去重（Semantic Deduplication）**：合并语义重复条目；评估前另执行 `pre_evaluation_semantic_deduplication`，避免近义条目进入施测矩阵；
3. 输出精简后的题项池，供 Phase 1 施测。

与 **单提示直出基线** 相比，本阶段差异不在“条目更少”，而在 **输入约束更完整**（访谈 + 文献机制 + 专家材料）与 **生成后筛选**（评估 + 去重），从而抑制构念漂移。定性对照实验显示：在相同肌肉骨骼场景、相同模型下，5 次直出 run 的条目数为 10～15 条不等，维度结构不稳定，且常出现“robot acted like a human colleague”等难核验表述；九步骤流水线则保持与失败模式对齐的可观察条目。

### 2.5 模拟施测与统计精简

#### 2.5.1 Phase 1：双组 Persona 施测（Selection）

题项池生成后，**评估智能体组（Evaluation Agent Group）** 进入 Phase 1（selection）。系统首先由 **Persona 生成智能体** 构造 empathic / non-empathic 两组虚拟被试，在统一场景描述下对全部候选题项进行 5 点李克特评分，形成模拟数据集，写入 `evaluation_agent_group/selection/combined/`。

该设计借鉴 PETS 的“对立共情条件”思路：高共情组应显著高于低共情组，从而支撑条目区分度评估。样本规模由实验脚本配置（如 200 participants），满足 EFA 对样本量与题项数的比例要求（系统内部约束：进入 EFA 的题项数通常不超过样本量的 80%）。

#### 2.5.2 统计选题：EFA / CFA

**统计选题模块（`utils/factor_analysis.py` + ItemSelectionAgent）** 对 Phase 1 数据执行 PETS 式多阶段筛选：

**Stage 1 预筛选（Step 1～3）**

- 题总相关（item-total correlation），保留相关 > 0.3 的条目；
- 分布检查（避免低方差、天花板/地板效应）；
- 自适应阈值，使约 35～50 条进入 EFA。

**Stage 2 探索性因子分析（EFA）**

- 提取因子结构，剔除因子负载不足的条目；
- 确定因子数（如 2 因子）及条目—因子归属。

**Stage 3 验证性因子分析（CFA）**

- 在 EFA 结构基础上检验拟合：RMSEA < 0.08，TLI/CFI > 0.9，SRMR 等；
- 若拟合不足或题项过多，迭代剔除负载最低条目直至达标或达到目标题量上限。

输出 `filtered_scale_draft.md` 作为统计筛选后的定稿候选。肌肉骨骼场景一次验证 run（2026-05-11_155408）由 36 条候选收敛为 **10 条**，呈现二维结构：

- **Coordination Communication**（协调沟通，6 条）：含手臂轨迹预判、同时伸手时的口头让行、误取后 verbal repair 等；
- **Shared Workspace Consideration**（共享工位考量，4 条）：含对取件位置的理解、同时伸手时的挫败感缓解、共享空间安全感等。

#### 2.5.3 Phase 2：独立样本验证（Validation）

在 **不再改动条目集合** 的前提下，Phase 2 使用 **独立 Persona 样本** 重新施测，计算：

- 内部一致性 Cronbach's α；
- 组间效应量 Cohen's d（empathic vs non-empathic）；
- 其他验证指标，写入 `evaluation_agent_group/validation/evaluation_summary.json`。

Phase 2 的定位是“定稿后检验”，避免在验证阶段再次改题造成循环调参，对应 Boateng 第九步“效度检验”及 PETS Scale Evaluation 精神。

## 4. 阶段性进展总结

本阶段围绕 **共情量表的生成方法** 形成可运行的技术路线，主要进展如下：

1. **理论对齐**：以 Boateng 九步为规范框架，与 PETS 六段流程建立一一映射，保证方法学可辩护性。
2. **场景驱动**：通过访谈结构化 + 场景因子 + 失败模式字段，将测量边界锁定在具体 HRC 情境。
3. **证据可追溯**：文献检索—机制卡片—Evidence Base 链条，使条目来源可审计。
4. **生成可控**：多生成器 + 内容评估 + 语义去重，相对单提示直出显著提升条目可核验性与结构稳定性。
5. **统计定稿**：双组 Persona 施测 + EFA/CFA 精简 + Phase 2 独立验证，输出如 10 条 2 因子结构的可用量表。
6. **对照验证**：定性 HTML 报告与定量基线对比证明，场景专用量表在共享工位协调、口头让行、几乎碰撞沟通等机制上优于 PETS 与直出基线。

**后续工作**包括：在更多场景（远程协作、面对面服务、不同机器人形态）复用流水线；引入真人被试数据校验 LLM Persona 施测的外部效度；扩展机制卡片与专家 CVI 的混合效度设计。
