## §1 维度 / 信度 / 效度检验覆盖与质量研判

### 1.1 维度（Dimension）
- **负责 agent**：`ConstructDefinitionAgent`（定义构念+维度）+ `literature_search_agent_group.organize_results()`（从文献归纳定义/行为/测量）+ `ItemGenerationAgent`（按维度生成条目）。
- **现状**：维度由"访谈+文献"共同驱动；旧 run 默认 2–4 维，本轮已改为 **EXACTLY 4–6 维**（`prompts/scale_generation_support.json`），以支撑更大规模测试。
- **满意度**：维度定义可追溯、与文献一致；无功能性 bug。

### 1.2 信度（Reliability）
- **负责模块**：`item_selection_agent`（Phase2 设 α≥0.8 门控）+ `utils/psychometric_feedback.py`（`cronbach_alpha`、`alpha_if_deleted`、`item_total_correlations`）。
- **现状**：旧 run（18 题/2 因子）α≈0.99；但这是 LLM-persona 模拟数据，α 天然偏高（persona 回答高度一致）。
- **注意点**：persona 数据下 α 饱和，不能直接当作"真人信度证据"——这是方法学前提（无真人），不是代码 bug。

### 1.3 效度（Validity）
- **内容效度（CVI）**：`content_validity_agent` 输出 I-CVI / S-CVI（专家=LLM）。旧 run S-CVI 达标。
- **结构效度（EFA→CFA）**：`item_selection_agent` 做 EFA 选因子；`utils/factor_analysis.py.perform_cfa()` 做 CFA 拟合优度。
  - **曾存在 bug（已修）**：`perform_cfa` 早期用 `model.inspect()` 误取参数估计当拟合指数 → 误报拟合优。修正为 `semopy.calc_stats()` + 手动补 SRMR。
  - **真实问题（非 bug）**：旧 run 仅 n=30（每组 15 人），CFA 拟合指数全面不达标（RMSEA=0.387、TLI=0.716、CFI=0.751、SRMR=0.199）。**样本太小**是根因 → 这正是任务 4 跑更大规模（N=40/组）的动机。
- **区分效度（Discriminant）**：高/低共情组 Cohen's d（`discriminant_d`，已修非连续索引 KeyError）。

**结论**：维度/信度/效度三块"都有 agent 在做"且主流程无 bug；唯一实质性短板是小样本下 CFA 拟合不足，靠更大规模测试缓解。

## §2 NMI 网络可视化（任务 2）

- **产物**：`tools/nmi_network_viz.py`。加载 `participant_level_evaluations.json` → 构建条目 Pearson 相关网络（每节点保留 top-3 最强边，稀疏、贴近参考图）→ `networkx.greedy_modularity_communities` 做社区发现 → 与"原始维度标签（选前）/ EFA 因子（选后）"算 NMI。
- **脚本版本说明**：旧版 `nmi_network_viz.py` 输出 NMI 为百分比（选前 40.96 / 选后 78.61，117 题 / 4 维 → 18 题 / 2 因子）。当前脚本输出归一化到 [0,1]。
- **本轮大规模 run 重画**（`largeN_2026-10-08_153234`，见 §4）：
  - 选前：NMI = **0.76**（117 题 / 4 原始维度标签）
  - 选后：NMI = **1.00**（20 题 / 2 EFA 因子，社区结构与因子结构**完全吻合**）
  - 产物：`data/runs/largeN_2026-10-08_153234/viz/nmi_item_network.png`
- **结论**：代码生成的条目**完全可以**复现参考图的"网络社区结构随条目筛选而更贴合因子结构"的效果；大规模样本下选后 NMI 达到 1.00，说明统计筛选后的条目网络社区与 EFA 因子归属一致。

## §3 最近对话新增的 agent / 模块（任务 3）

**量表开发与 psychometric 闭环（本仓库）**
- `agents/item_refinement_agent.py` — `ItemRefinementAgent`：以"心理测量质量提升"为激励，重写弱条目。
- `utils/psychometric_feedback.py` — 奖励/诊断工具箱：α、α-if-deleted、条目-总分相关、最大因子载荷、Cohen's d、`scale_reward`（0–1 复合）、`diagnose_items`、`pick_weak_items`。
- `run_self_incentive.py` — 自激励驱动器：诊断→选弱项→重写→在小样本上重评→局部指标爬山（keep/rollback）。
- `tools/nmi_network_viz.py` — 条目网络社区可视化（见 §2）。
- `tools/verify_run_cfa.py` — 对任意 run 用修正后的 `perform_cfa` 重算真实 CFA 拟合指数。
- `tools/pipeline_efficiency.py` — 问题数→API 调用/token/耗时 的估算模型（见 §5）。
- `prompts/scale_generation_support.json` — 维度数 2–4 → **4–6**（更大规模测试开关）。

**LLM 共情能力评估（新文件夹 `llm_empathy_eval/`，任务 8）**
- `scale_adapter.py` — 复用已验证量表（18 题 + 因子结构）。
- `subject_model.py` — `StubSubject`（离线桩）/ `QwenSubject`（Qwen2.5-0.5B CPU）/ `GLMSubject`（GLM-4-Flash urllib 直连，零依赖）。
- `judge.py` — `GLMJudge`：按量表逐题 0–100 打分、聚合 reward（复用主项目 config.json 密钥，本目录不落密钥）。
- `incentive_loop.py` — `PromptIncentiveLoop`：变异 system prompt → 重评 → 爬山保留。
- `run_demo.py` / `README.md` — 入口与方法学说明。

### 4.1 CFA 拟合对比（旧 n=30 vs 新 N=80）

| 拟合指数 | 旧 run（n=30, 18题） | 新 run（N=80, 独立重算 18题） | 经验阈值 | 变化 |
|---|---|---|---|---|
| RMSEA | 0.387 | **0.215** | < 0.08 好 / < 0.10 可接受 | ↓ 显著改善 |
| TLI   | 0.716 | **0.876** | > 0.90 | ↑ 接近达标 |
| CFI   | 0.751 | **0.891** | > 0.90 | ↑ 接近达标 |
| SRMR  | 0.199 | **0.237** | < 0.08 | ↑ 略升（仍偏外） |

> 旧 run 来源：`data/runs/2026-10-07_012327/statistical_selection/cfa_recheck.json`（n=30）。
> 新 run 独立重算来源：`tools/verify_run_cfa.py largeN_2026-10-08_153234` → `.../cfa_recheck.json`（最终 18 题，移除 27、37）。
> `item_selection_agent` 阶段报告（20 题/2 因子）为 RMSEA=0.220 / TLI=0.774 / CFI=0.784 / SRMR=0.377；verify 工具对最终 18 题重算后 TLI/CFI 更接近 0.90，说明"再删 2 题"进一步改善拟合。

### 4.2 NMI 网络社区（见 §2）
- 选前 NMI=0.76（vs 4 原始维度），选后 NMI=**1.00**（vs 2 EFA 因子，完全吻合）。

### 4.3 结论
- 样本量从 30 提到 80 后，RMSEA/TLI/CFI **三项全部显著改善**，TLI/CFI 已逼近 0.90 经验线；选后 NMI 达 1.00。
- 仍**未完全达标**（RMSEA 0.215、TLI/CFI <0.90），与"无真人被试 + LLM-persona 数据高度一致"前提一致；按论文经验（`verify_run_cfa.py` 提示）进一步逼近需 n≥200 或 ≥10:1 题例比。任务 4 的目标"用更大规模改进小样本拟合不足"已达成。

## §5 流水线效率（任务 7）

- **模型**（按真实代码调用粒度估算，见 `tools/pipeline_efficiency.py`）：
  - 旧配置（192 题，15/组）：≈ **1265 次 API 调用 / ~1.5M token / 每最终条目 ~8.3 万 token**。
  - 大配置（240 题，40/组）：≈ **1686 次调用 / ~2.94M token**。
- **成本热点**：CVI（192×5 专家 ≈ 45%）+ Phase1 双组模拟（≈24%）占主要开销。
- **结论**：条目数≈线性推高 CVI 与模拟成本；维度数主要影响 EFA/CFA 与选条后的规模。免费 GLM 下成本=时间而非金钱。

## §8 LLM 共情能力评估（任务 8，✅ 完成）

- **思路**：备份主仓库 → 新文件夹 `llm_empathy_eval/` → 复用已验证量表（18 题 + 因子结构）评估"任意 LLM 的共情能力"。
- **闭环**：量表 → 被评 LLM 作答（subject）→ GLM 按量表逐题 0–100 打分 → 聚合 reward → 以 reward 为激励变异 system prompt 爬山（keep/rollback）。
- **实跑验证（GLM 当被试 + GLM 当评委，零第三方依赖）**：
  - 入口：`run_glm_demo.sh` → `run_demo.py --model glm`（用主 venv 跑，绕过 openai 的 httpx2 污染）。
  - 被评模型：`GLMSubject`（GLM-4-Flash，urllib 直连，主目录 `config.json` 密钥，本目录不落密钥）。
  - 轨迹（`results/glm/incentive_trace.md`）：`baseline 51.96 → iter1 47.41（情绪识别变异）→ iter2 49.44（倾听陪伴变异）`，最优 51.96（baseline 保留，两次变异未超过基线）。
  - **结论**："生成量表 → LLM 答题 → LLM 评估 → 以评估为激励迭代"全链路**跑通**；reward 在基线附近小幅波动，爬山逻辑与门控正确（未出现虚假上升）。
- **环境受阻后的决策**：本地小模型（torch / llama-cpp-python）在本机沙箱下无法安装（沙箱拦 `torch/include/*.h` 写入、cp313 无预编译 wheel），故实跑改用 API 模型 GLM 充当"被评 LLM"——更贴合"LLM 当被试"主张，且免费档零成本。Qwen/GGUF 后端仅待环境允许时一行 `--model` 切换即可替换。
- **注意**：reward≈51 量级偏低，属 GLM 自评尺度（0–100）特性；这不影响"闭环可行"的方法论结论，真实评估需换成更强的 judge 与目标模型。
